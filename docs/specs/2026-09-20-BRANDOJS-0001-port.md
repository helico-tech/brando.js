# Durable TypeScript port

Reference: helico-tech/brando at 6a07d99, particularly the v1 architecture §§7–14, production TurnKernel and Store. Port behavior, not the Kotlin implementation or database schema. No shared database compatibility is promised.

Implement a Node 24 library with explicit durable codec identities and runtime validation, a framework-independent turn kernel, PostgreSQL coordination with ordered mailboxes, monotonically fenced leases, atomic outcomes/sends/reminders, finite result retention, resumable callers, typed failures, graceful shutdown and schema management. Ordinary application exceptions are terminal; runtime interruptions are retried. Direct mutation without update is discarded. A test kit uses the production kernel.

Ship rate limiter, recurring schedule, retry runner and heartbeat monitor as ordinary actors. A framework-neutral Fetch API adapter exposes authenticated operations; a bundled React/shadcn dashboard inspects real runtime data and submits/resubmits messages. The example runs a real PostgreSQL-backed application.

Validation: unit tests written before implementation; serial PostgreSQL tests with fresh schemas, two-replica/fencing tests, package consumer checks, real start scripts, before/after Playwright CLI screenshots, and repeatable browser tests. Publish a public GitHub repository only after checks pass.
